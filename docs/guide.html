User documentation

Set up the applet

Install FRITZ!Power Monitor, connect supported FRITZ!Box and Tasmota power meters, optionally pair a Philips Hue Bridge, and customize the COSMIC panel.

Requirements

  • A COSMIC desktop session with panel applet support.
  • A FRITZ!Box with Smart Home support and a user account allowed to read Smart Home data. The router's local IPv4 network is also used as the target range for Tasmota discovery.
  • For power graphs and totals, at least one compatible FRITZ!Box Smart Home or Tasmota power meter. Temperature can come from supported FRITZ!Box devices or from compatible Philips Hue environment sensors.
  • Optional Philips Hue lights and environment sensors require a reachable Hue Bridge on the local network, physical link-button pairing, and compatible CLIP v2 resources. Hue lights do not provide wattage measurements.
  • For source builds: Rust, Cargo, GNU Make and the standard GNU install utilities.

FRITZ!Box, Tasmota and Hue integration use local network connections. The Hue Bridge is optional and independently refreshed; weather is optional and uses external services.

Installation

Install the latest portable archive

Download the latest .tar.gz from the project website, then extract it and install the executable, desktop entry and icon for your user:

tar -xzf fritz-power-monitor-vVERSION-x86_64-unknown-linux-gnu.tar.gz
cd fritz-power-monitor-vVERSION-x86_64-unknown-linux-gnu

install -Dm755 bin/fritz-power-monitor ~/.local/bin/fritz-power-monitor
install -Dm644 share/applications/com.gpkvt.FritzPowerMonitor.desktop ~/.local/share/applications/com.gpkvt.FritzPowerMonitor.desktop
install -Dm644 share/icons/hicolor/scalable/apps/com.gpkvt.FritzPowerMonitor.svg ~/.local/share/icons/hicolor/scalable/apps/com.gpkvt.FritzPowerMonitor.svg

Replace VERSION with the version in the downloaded filename. This user-local installation does not require root privileges. Once installed, add the applet to a panel using the steps below.

Install from a source checkout

git clone https://github.com/gpkvt/cosmic-ext-fritzsmart-monitor-applet.git
cd cosmic-ext-fritzsmart-monitor-applet
make install

This builds the release binary and installs it under ~/.local. The default Makefile target updates the checkout first; use make install UPDATE=0 to skip that update.

Build and validate manually

cargo fmt --all -- --check
cargo test
cargo build --release

For source-build prerequisites, see the repository README.

Install and add custom applets in COSMIC

COSMIC discovers panel applets through desktop entry files. A native applet normally installs its executable somewhere on your PATH, its desktop entry in ~/.local/share/applications (for a user install) or /usr/share/applications (for a system install), and any required icons in the matching icon theme directory.

  1. Install the applet. Follow its own instructions. For a user-local install, ~/.local/bin and ~/.local/share are the usual locations; root access is not needed.
  2. Check its desktop entry. The .desktop file should contain X-CosmicApplet=true. Its Exec command must resolve to the installed executable. An ordinary desktop launcher without the COSMIC applet key will not be offered as a panel applet.
  3. Add it to the panel. Open COSMIC Settings → Desktop → Panel, open the panel applet configuration, choose Add applet, then select the applet. Place it in the Start, Center or End section as desired.
  4. Refresh discovery if needed. Close and reopen COSMIC Settings. If the applet still does not appear, log out and back in to refresh the desktop entry cache and panel applet list.

The exact wording and placement of these controls can differ between COSMIC versions. These steps describe native applets; Flatpak applet discovery can depend on the applet's Flatpak export and COSMIC version.

For the applet desktop-entry keys and panel architecture, see the COSMIC Toolkit panel applet documentation.

First launch

  1. Open COSMIC Settings and add FRITZ!Power Monitor from the panel applet list.
  2. Open the applet popup and choose Settings.
  3. Open Connection, enter the FRITZ!Box URL, username and password, then select Load devices.
  4. Choose the devices to monitor and save your settings.

If the applet does not appear in COSMIC Settings after installation, reopen Settings or log out and back in.

Connect to your FRITZ!Box

Enter the router address (for example https://fritz.box/), the FRITZ!Box username and its password in the applet's Connection settings. The account must be permitted to access Smart Home data.

HTTPS certificate validation is enabled by default. If your router uses a self-signed certificate, provide its PEM certificate in Trusted CA certificate. The certificate is added as a trust anchor; normal certificate-chain and hostname checks remain enabled.

openssl s_client -connect fritz.box:443 -showcerts

Use a hostname present in the certificate's Subject Alternative Name (SAN). The compatibility option Allow invalid TLS certificates disables certificate verification and is not recommended.

Choose devices and understand power values

Select the devices you want to monitor. Each one gets an expandable card with current readings and power history; supported switches can be controlled from the popup.

Input devices

Enable Input for devices measuring consumption or another signed input. Input and output power are shown independently in the combined history graph and in separate current/daily energy values; they are not subtracted from each other. Devices with solar in their name are initially marked as inputs; later manual changes are preserved. Until at least one device is configured as an input, solar/input readings, combined energy metrics, percentages and input graphs are hidden. Output-only graphs, daily output values and energy history remain available. The Input device control is always available in Devices settings, even when no inputs are configured. Once a device is marked as input, solar features remain visible during temporary disconnections.

Tasmota devices

Tasmota smart plugs and power meters appear in the same device inventory as FRITZ!Box Smart Home devices. Their live power readings feed individual device cards, history and the shared Total power input and Total power output readings. Supported relays can also be switched from the popup.

Saved Tasmota devices and their addresses are loaded when the applet starts, so they are available straight away. Startup uses mDNS discovery and does not scan the whole subnet. To find new devices, open Settings → Devices and start Search for devices. The search shows progress, uses mDNS and scans the same IPv4 /24 subnet as the FRITZ!Box address when that address is configured as an IP. For example, 192.168.42.1 scans 192.168.42.2 through 192.168.42.254. If the router URL uses a hostname, the subnet scan is skipped and mDNS is still used.

New devices are added to the device list. Select them to include their readings; discovery does not remove devices you have already configured. Tasmota temperature sensors are not currently supported, so Tasmota cards provide power but no temperature readings or temperature alerts.

Philips Hue Bridge: lights and sensors

Connect an optional Hue Bridge locally from Settings → Connection → Philips Hue Bridge. The applet discovers bridges on the local network with mDNS and fills the IP automatically when exactly one bridge is found; select one from the discovered list if several are available. Use Find Hue Bridge automatically to rescan. If mDNS fails, enter the private IP address manually (without a URL scheme). Choose Pair Hue Bridge, then press the physical link button within 30 seconds; the applet retries while it waits, and shows status directly beside the control. You can also enter an existing application key. Manage Hue lights and sensors under Settings → Devices in the same searchable, sortable list as FRITZ!Box and Tasmota devices, with a visibility checkbox and +/− ordering controls per device. Hue lamps can also be switched from their settings row. The popup Devices section displays the chosen Hue lights and sensors; expand sensors for motion state and view temperature in °C/°F and illuminance in lux. Hue Bridge credentials and pairing remain in Settings → Connection. Missing watt values remain unavailable, not zero. Expanded Hue sensor rows now contain individually collapsible temperature (°C/°F) and illuminance (lux) graphs. The graphs use real persisted readings only and follow the graph time-range setting. Per-sensor high/low temperature alarms can be enabled and configured under Settings → Devices; missing or disconnected measurements do not trigger notifications.

The applet checks Hue lights and sensor readings every 60 seconds, independently of the FRITZ!Box and Tasmota connections. Readings use the bridge's separate temperature, light-level and motion resources, grouped under the physical sensor name. Disabled, invalid or disconnected measurements display as unavailable rather than zero. Philips Hue light resources provide control but generally do not expose consumption measurements, so they do not contribute to watts, temperature, energy or history charts. Scenes, groups, brightness and changing sensor configuration are not supported in this release; sensor temperature and illuminance readings are read-only.

Compatibility summary: Hue lights expose on/off state and controls, but not metered watts or energy. Compatible Hue environment or motion sensors may expose temperature (°C/°F), illuminance (lux) and motion state; only values actually provided by the sensor are displayed and recorded. Supported temperature and light measurements have independent history graphs, and valid temperature readings may contribute to the panel average and optional temperature alerts. The applet does not currently manage Hue brightness, scenes, rooms or sensor configuration.

TLS note: The Hue Bridge uses a Hue-specific certificate issued to its bridge ID, not its IP. For local IP access the Hue-only HTTPS client skips certificate verification; older bridges can use a fallback HTTP registration request when HTTPS pairing cannot connect. Use a trusted LAN and protect your bridge application key. Other API connections preserve their certificate validation settings.

Panel and popup layout

Set the panel text size (10–24 pt). You can also show the average temperature of selected devices and enable Show internet bandwidth to add separate download and upload rates in Mbps with directional icons. Bandwidth is read from the FRITZ!Box WAN interface statistics; if the router firmware does not expose these values, the readings remain unavailable without interrupting Smart Home monitoring. The average temperature can exclude devices whose names contain solar. Visible, reachable Hue sensor temperatures are also included in the panel average; unselected or unavailable measurements are excluded. Hover directly over a panel value for a native COSMIC tooltip showing the reporting device name, aggregate contributor names for power totals, or Average temperature for an averaged temperature value. Hover never opens the main menu. The installed desktop entry deliberately omits X-CosmicHoverPopup: COSMIC Panel interprets that key's presence as an instruction to synthesize pointer clicks on hover. Multiline panel items use intrinsic, shrink-wrapped widths to avoid conflicting sizing when readings update.

Use Menu order and Device order in Settings to arrange the popup sections and device cards. Current Power History contains the combined input/output history graph. Total Power Input & Output shows OUTPUT LOW/HIGH and INPUT LOW/HIGH tiles alongside its numeric and daily energy summaries, plus full-width input/output power-history graphs. Input tiles stay visible if no device is currently reporting, using recorded history where available and showing an em dash rather than 0 W if no history exists. Collapse top-level sections, individual device cards and their graphs independently. The popup remembers expanded/collapsed states across restarts, including Quick Settings, weather and diagnostics history JSON. The saved order is preserved; the popup scroll position is not. Collapsed headings keep current readings when available. The popup occupies the available monitor height outside the COSMIC panel, with Wayland allowed to resize it vertically when the dock or other display constraints leave less room; there is no longer an arbitrary 85% monitor-height cap. The title bar and footer stay fixed while the popup content scrolls to fit. Click the panel entry to open the popup. Clicking outside the popup closes it using the compositor's native outside-click handling; the popup also has a Close button, and the panel entry can toggle it closed. Hovering over the panel does not open the menu or spawn per-reading tooltip popups. The Total Power Input & Output section includes full-width input/output watt-history graphs (covering current, low and high readings) and separate recorded daily input, output and input/output percentage trends for the last seven days. Missing days are not plotted as zero. Every overview graph has its own independent expand/collapse chevron; those choices persist across restarts and remain unchanged when collapsing or reopening the whole overview. The overview stays available when history is empty and uses an em dash for missing ranges. The Daily Energy · Last 7 Days table includes a separate input/output percentage for each day (solar Wh ÷ grid Wh × 100), and its collapsed heading shows today's ratio. Missing readings or zero grid usage show an em dash rather than a misleading zero percent. The popup title shows the installed version.

Optional weather integration

Weather requires an OpenWeatherMap API key. Enable Use current weather icon, enter the key and specify a city or coordinates in latitude,longitude format. Weather refreshes independently every 5–60 minutes (10 minutes by default).

The panel can show the current condition icon and temperature. The popup adds feels-like temperature, humidity, wind, pressure, cloud cover, visibility, sunrise and sunset. Weather imagery is illustrative Wikimedia Commons photography, not a live camera view, and includes attribution.

Temperature alerts

Enable alerts per device to receive desktop notifications outside the configured temperature range. Defaults are 40 °C (upper) and −10 °C (lower). Alerts are disabled by default, fire when a device crosses a limit and re-arm after the reading returns to the safe range.

Graphs and history

In Settings, choose how much graph history to keep (from 5 minutes to 4 years). The applet saves samples locally and reloads them after a restart. Sampling adjusts to the selected period and is capped at about 50,000 samples per series. Samples are stored locally in ~/.local/share/fritz-power-monitor/history.json with owner-only file permissions and restored after restarting the applet. The popup estimates daily solar input and grid consumption in Wh for the last 7 days from recorded samples. This is not an inverter-specific yield forecast. Settings and disclosure state are stored separately in ~/.config/fritz_solar.cfg.

Security and privacy

  • FRITZ!Box authentication uses the challenge-response mechanism.
  • HTTPS certificate validation is enabled by default; a router-specific CA can be added without disabling hostname checks.
  • Router credentials, the Hue application key, and the optional weather API key are stored in ~/.config/fritz_solar.cfg with owner-only permissions.
  • Core monitoring communicates directly with the router. OpenWeatherMap and Wikimedia Commons are contacted only for optional weather features.

Never include passwords, API keys or private router details in bug reports. See SECURITY.md for reporting vulnerabilities.

Troubleshooting

Readings briefly appear, then the applet disappears

This symptom was resolved in the reported COSMIC setup with v2.0.45. The fix removed the desktop-entry key X-CosmicHoverPopup (which caused COSMIC Panel to generate hover clicks), and made nested multiline panel rows shrink-wrap their content. Updating only the binary is not sufficient: reinstall the applet so the corrected .desktop entry is used.

make install
grep -H '^X-CosmicHoverPopup=' ~/.local/share/applications/com.gpkvt.FritzPowerMonitor.desktop \
  || echo 'Click-only panel entry installed'

The grep command should show no matching entry. For a system-wide package, also check /usr/share/applications/com.gpkvt.FritzPowerMonitor.desktop; an outdated user-local override takes precedence and should be updated or removed. Reload COSMIC Panel after the update. If the applet still exits unexpectedly, inspect its syslog entries with journalctl -b -t fritz-power-monitor -p debug -n 120 --no-pager; a successful device refresh alone does not prove that device loading caused the exit.

The applet is missing from COSMIC Settings

Reopen COSMIC Settings. If it is still missing, log out and back in so the desktop can refresh applet discovery.

No devices are listed

Check that the router URL and credentials are correct, the account has Smart Home permissions, and the FRITZ!Box exposes compatible Smart Home devices. For Tasmota, confirm that devices are reachable on the FRITZ!Box local /24 network or advertise themselves through mDNS, then start a search from Devices settings. A hostname-based FRITZ!Box URL disables subnet scanning but not mDNS discovery.

The router connection fails with a certificate error

Check the URL hostname against the certificate's SAN. If the router uses a self-signed certificate, add its PEM certificate as a trusted CA instead of disabling TLS verification.

Weather is unavailable

Check the API key, location and network connection. Weather is optional, so a weather request failing does not stop router monitoring.

Graphs are empty after restarting

Graph history is normally restored from ~/.local/share/fritz-power-monitor/history.json. Check that the file exists and is readable by your user. History is updated from successful refreshes and limited to the configured 5-minute to 4-year retention window, using an adaptive sampling interval capped at about 50,000 samples per series. A new or expired history file may have no samples to display.

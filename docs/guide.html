User documentation

Set up your home energy view.

Install FRITZ!Power Monitor, connect it to your FRITZ!Box, choose the devices you want to monitor and tune the applet to your COSMIC desktop.

Requirements

  • A COSMIC desktop session with panel applet support.
  • A FRITZ!Box with Smart Home support and a user account allowed to read Smart Home data.
  • At least one compatible device exposing power and temperature measurements.
  • For source builds: Rust, Cargo, GNU Make and the standard GNU install utilities.

The applet talks directly to the FRITZ!Box on your local network. The optional weather feature uses external services and can remain disabled.

Installation

Install from a source checkout

git clone https://github.com/gpkvt/cosmic-ext-fritzsmart-monitor-applet.git
cd cosmic-ext-fritzsmart-monitor-applet
make install

The recommended user-local installation needs no root privileges. The Makefile pulls the configured upstream with git pull --ff-only, builds the release binary and installs it under ~/.local.

Build Linux packages

On an x86_64 Linux host, build Debian, AppImage and Flatpak packages with:

APP_VERSION=0.3.0 bash packaging/build-linux-packages.sh

Packages and SHA-256 checksums are written to dist/ by default. See the Releases page for published builds.

Build and validate manually

cargo fmt --all -- --check
cargo test
cargo build --release

For the complete package prerequisites and options, see the repository README.

First launch

  1. Open COSMIC Settings and add FRITZ!Power Monitor from the panel applet list.
  2. Open the applet popup and choose Settings.
  3. Open Connection, enter the FRITZ!Box URL, username and password, then select Load devices.
  4. Choose the devices to monitor and save your settings.

If the applet does not appear in COSMIC Settings after installation, reopen Settings or log out and back in.

Connect to your FRITZ!Box

Enter the router address (for example https://fritz.box/), the FRITZ!Box username and its password in the applet's Connection settings. The account must be permitted to access Smart Home data.

HTTPS certificate validation is enabled by default. If your router uses a self-signed certificate, provide its PEM certificate in Trusted CA certificate. The certificate is added as a trust anchor; normal certificate-chain and hostname checks remain enabled.

openssl s_client -connect fritz.box:443 -showcerts

Use a hostname present in the certificate's Subject Alternative Name (SAN). The compatibility option Allow invalid TLS certificates disables certificate verification and is not recommended.

Choose devices and understand power values

Select the compatible devices discovered from the router. Each selected device has its own expandable card with live readings, power history and temperature history. Supported switches can be controlled from the popup.

Input devices

Enable Input (subtract from total) for devices measuring consumption or another signed input. Input wattage is tracked separately and does not change Total power output. Power difference combines output with signed input wattage. Devices with solar in their name are initially marked as inputs; later manual changes are preserved.

Panel and popup layout

Choose the panel text size (10–24 pt) and optionally show average temperature across selected devices. The average can exclude devices whose names contain solar.

Use Menu order in Settings to arrange the popup's summary, weather, device cards and power overviews. Device cards keep their relative order. Collapse top-level sections independently; each collapsed heading keeps its primary live value visible. Collapsed device rows continue to show power and temperature. The popup title bar provides Refresh and Settings while its content scrolls independently.

Optional weather integration

Weather requires an OpenWeatherMap API key. Enable Use current weather icon, enter the key and specify a city or coordinates in latitude,longitude format. Weather refreshes independently every 5–60 minutes (10 minutes by default).

The panel can show the current condition icon and temperature. The popup adds feels-like temperature, humidity, wind, pressure, cloud cover, visibility, sunrise and sunset. Weather imagery is illustrative Wikimedia Commons photography, not a live camera view, and includes attribution.

Temperature alerts

Enable alerts per device to receive desktop notifications outside the configured temperature range. Defaults are 40 °C (upper) and −10 °C (lower). Alerts are disabled by default, fire when a device crosses a limit and re-arm after the reading returns to the safe range.

Graphs and history

Configure the history window from 5 minutes to 24 hours. Samples are collected after successful refreshes and shown in total-power and per-device graphs. Graph samples are stored locally in ~/.local/share/fritz-power-monitor/history.json with owner-only file permissions and restored after restarting the applet. The configured history window (5 minutes to 24 hours) is retained across restarts; this does not provide daily yield, forecasts or inverter-specific statistics.

Security and privacy

  • FRITZ!Box authentication uses the challenge-response mechanism.
  • HTTPS certificate validation is enabled by default; a router-specific CA can be added without disabling hostname checks.
  • Router credentials and the optional weather API key are stored in ~/.config/fritz_solar.cfg with owner-only permissions.
  • Core monitoring communicates directly with the router. OpenWeatherMap and Wikimedia Commons are contacted only for optional weather features.

Never include passwords, API keys or private router details in bug reports. See SECURITY.md for reporting vulnerabilities.

Troubleshooting

The applet is missing from COSMIC Settings

Reopen COSMIC Settings. If it is still missing, log out and back in so the desktop can refresh applet discovery.

No devices are listed

Check that the router URL and credentials are correct, the account has Smart Home permissions, and the FRITZ!Box exposes compatible Smart Home devices.

The router connection fails with a certificate error

Check the URL hostname against the certificate's SAN. If the router uses a self-signed certificate, add its PEM certificate as a trusted CA instead of disabling TLS verification.

Weather is unavailable

Weather is optional. Check the API key, location and network connectivity; router monitoring continues independently when weather requests fail.

Graphs are empty after restarting

Graph history is normally restored from ~/.local/share/fritz-power-monitor/history.json. Check that the file exists and is readable by your user. History is collected after successful refreshes and is limited to the configured 5-minute to 24-hour window, so an empty or expired history file may have no samples to display.
